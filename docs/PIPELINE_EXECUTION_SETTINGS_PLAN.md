# Настройки агентов и моделей: план внедрения

Статус: реализовано и развёрнуто (`04ddae1`); результаты production-приёмки — в
[corrective log](PIPELINE_CORRECTIVE_ACTION_LOG.md). Исходный план проверен
по коду `ca496d4` и локальному Codex CLI `0.159.0` 2026-09-29.
Запрос пользователя разрешает менять число включённых исполнителей вместо
прежнего обязательного заполнения всех восьми. Остальные правила
[AGENTS](../AGENTS.md) и [corrective log](PIPELINE_CORRECTIVE_ACTION_LOG.md) сохраняются.

## Поведение в админке

На странице Pipeline добавить блок «Агенты и модели»:

- **Включено агентов:** удобный выбор 1–8 с прямым вводом числа; общий пул
  для всех AI-этапов. Полная остановка остаётся отдельной кнопкой Pause.
- **Luna:** модель для обычных задач и поддерживаемый уровень рассуждения.
- **Luna High:** независимый выбор модели и уровня для расширенных задач.
  Одинаковую модель можно выбрать в обоих профилях.
- **Сохранить / Отменить изменения**, состояние сохранения и понятная ошибка.
  Показывать заданное число, фактические запуски и завершающиеся лишние агенты.
  В Agent Runs показывать профиль, модель, уровень и версию настроек.

Отдельная страница **Agents & Models**: сравнение моделей, сортировка по цене
входа/выхода, быстрый выбор для обоих профилей. Загружать официальные тарифы
Standard Codex с кэшем, датой и ссылкой; сохранять последний успешный результат
при сбое. Рядом показывать фактические семидневные запуски, ошибки, длительность
и проверки Fidelity, явно обозначая отсутствие данных и ограниченность выборки.

Luna/High — роли, а не названия конкретных моделей. Исходное соответствие:

| Профиль | Задачи | Начальные настройки |
| --- | --- | --- |
| Luna | Expert, Discover, Refresh, Analyze, Verify, Deep Low | `gpt-5.6-luna`, `low` |
| Luna High | Demand diagnosis, Deep Medium | `gpt-5.6-luna`, `medium` |

Смена уровня рассуждения не меняет тип проверки, приоритет и размер контекста.
Название High не навязывает `reasoning=high`. Текущий резерв Terra для High
показать в дополнительных настройках как явно заданную резервную модель;
дать возможность отключить его. Основная и резервная модели, причина перехода
и расход видны в журнале. Скрытых замен выбранной модели быть не должно.

Новые настройки действуют при следующем резервировании AI-задачи. Запущенная
задача сохраняет модель до завершения. При 8 → 2 число активных запусков может
временно превышать 2: новые запрещены до освобождения мест, текущие завершаются.
При увеличении разрешённые места сразу доступны. Pause сохраняет принудительную
остановку в пределах существующего десятисекундного контракта.

## Каталог Codex и стоимость

Каталог получать через `codex app-server` → `model/list` с пагинацией,
из **того же бинарника, окружения авторизации и эффективных ограничений**, что
использует macOS pool. Backend работает на Linux и не должен строить список
по своему аккаунту. Pool публикует ограниченный каталог через researcher bridge;
админка читает его через backend. Обновление каталога не запускает inference.

Хранить model ID, название, доступные уровни, версию CLI и время обновления.
Новые модели появляются без выпуска приложения. Показанный список не является
доказательством успешного доступа к inference: ошибки доступа и совместимости
обрабатываются явно. Нужны структурированный результат и web research для
соответствующих задач; эти возможности проверять отдельно от `model/list`.
Не разрешать режимы, требующие отключённых инструментов или автоматического
делегирования: восемь мест должны оставаться реальным пределом исполнений.

При недоступном каталоге показывать последний результат с датой и ошибкой;
сохранённую модель не заменять. Для смены модели требовать актуальный каталог;
изменение только количества агентов не зависит от доступности каталога.
Существующую исчезнувшую модель показывать явно и предлагать замену.

CLI вернул девять доступных моделей, включая `gpt-6-luna` и `gpt-6.1-sol`.
После выпуска `gpt-6-luna`/low успешно выполнила production web-задачу;
`gpt-6-luna`/medium — High-задачу через реальный executor на отдельной базе.
Остальные модели каталога не проверены на inference этой приёмкой.
Обнаруженный отсутствующий путь Codex в `.secrets/researcher-bridge.env`
исправлен; executable/version/нужные CLI-флаги проверены локально.
Не подменять исполняемый файл автоматически при ошибке конфигурации.

Тарифы Standard Codex на дату проверки, credits за миллион токенов:

| Модель | Вход | Кэшированный вход | Выход |
| --- | ---: | ---: | ---: |
| GPT-5.6 Luna | 5 | 0.5 | 30 |
| GPT-6 Luna | 2.5 | 0.25 | 12.5 |

GPT-6 Luna — кандидат для обоих профилей после проверки качества. Экономию
оценивать по фактическим токенам, повторным попыткам и результатам Fidelity.
Автоматической смены модели при миграции нет. Тарифы API и лимиты подписки
отличаются от этой таблицы. Новый запрос пользователя расширяет UI до загрузки
тарифов с фиксированного официального URL: обновление по кнопке и кэш на шесть
часов, без обещания фиксированной экономии или выдуманной оценки качества.

Источники: [каталог App Server](https://learn.chatgpt.com/docs/app-server#models),
[тарифы Codex](https://learn.chatgpt.com/docs/pricing).

## Хранение и совместимость

Следующая свободная миграция сейчас `043`; проверить номер перед реализацией.
Использовать дополнительные таблицы/поля без переписывания старых миграций:

- Два профиля в `pipeline_execution_profiles`: `profile_id`, `model`,
  `reasoning_effort`, необязательный резервный model/effort. Каталог runtime
  валидирует комбинацию; строки ограничены по длине и допустимым символам.
- Использовать существующий `max_concurrent_ai_runs` с диапазоном 1–8;
  добавить `settings_version`. Сохранение всех полей атомарно, с ожидаемой
  версией для защиты от перезаписи другой вкладкой и аудитом before/after.
- В задачах выделить `execution_profile`; для старой очереди вывести его
  из типа задачи и прежнего low/medium. Дальнейшая маршрутизация использует
  профиль, а не выбранный reasoning. Старое поле low/medium сохранить для
  совместимости, отделив от фактического уровня нового запуска.
- При claim сохранять в `agent_runs` снимок профиля, model, effort и версии
  настроек. Ответ bridge передаёт эти значения без нормализации к Luna/low.
- Pool сообщает версию протокола и возможности исполнителя. Несовместимому
  старому клиенту возвращать необходимость обновления до выдачи lease;
  не резервировать задачу, модель которой он не умеет запустить.
- Новые circuit breakers хранить отдельно с ключом профиль + тип задачи +
  model + effort. Ошибка старой модели не блокирует выбранную новую; результаты
  завершающихся старых запусков изменяют только свой circuit. Старую таблицу
  сохранить для отката; перенос её открытых circuits привязать к старым моделям.

`control_generation` остаётся механизмом Pause/Resume: обычное сохранение
настроек его не увеличивает и не отменяет leases. Legacy-поля БД
`ai_model/reasoning_effort` оставить со старыми значениями для отката бинарника;
новый runtime читает профили. В прежних API-полях отображать основной профиль,
а новые поля добавить обратно совместимо. Проверить ограничения reasoning в
`agent_runs` и новых таблицах; старые маршрутизирующие CHECK low/medium сохраняются.
Состояние каталога хранить отдельно от настроек и heartbeat занятых исполнителей.

Число мест контролируется backend: короткая атомарная транзакция резервации
не допускает превышения N при параллельных claims. Сохранение N согласовано
с этой резервацией. Не держать общий lock во время планирования, внешнего вызова,
подготовки большого payload или heartbeat. Supervisor может сохранять восемь
дешёвых координаторов; отключённые места сообщают `disabled` и не запускают Codex.
Авторизация исполнителя и общий лимит должны исключать обход через другое имя.
Никаких отдельных лимитов этапов: полезная работа заполняет весь разрешённый пул.

В Codex запускать точно `-m <model>` и
`-c model_reasoning_effort="<effort>"` из снимка claim через массив аргументов.
Неизвестные значения отклонять, не преобразовывать к low. Сохранить ephemeral,
read-only sandbox, изоляцию секретов/MCP/plugins, схемы результата, ограничения
контекста и прежнее распределение web-доступа. Ошибка доступа к модели не должна
вызывать бесконечные платные повторы или остановку независимого профиля.

Записывать происхождение каждого результата через соответствующий `agent_run`.
Если source processing run содержит разные модели после смены настроек,
отображать состав фактических запусков, а не одно выдуманное имя. Исторические
результаты не переименовывать. Ключ Fidelity включает модель/уровень извлечения,
версии extractor/prompt и модель проверки; новая комбинация получает отдельную
статистику и существующую полную выборку QA. Изменение только N не сбрасывает QA.
Отсутствие необязательной телеметрии не блокирует корректный артефакт.

## Порядок внедрения и приёмка

1. **Контракты и миграция.** Добавить профили, версию, снимки и отдельные circuits;
   сохранить исходные 8/Luna-low/Luna-medium/Terra, проверить grants и откат.
2. **Каталог и настройки.** Добавить bridge, API, аудит и проверку возможностей
   установленного Codex. Каталог обновляет один pool, а не восемь процессов.
3. **Планировщик и исполнение.** Провести профиль до subprocess, обеспечить N,
   плавное уменьшение, Pause, происхождение и отдельную статистику Fidelity.
4. **Админка.** Добавить удобный выбор и состояния; обновить подписи и demo.
5. **Проверки.** Выполнить `pnpm check`, `pnpm test`, `pnpm build`; сохранить
   регрессии leases, dedupe, публикации, provenance, web-изоляции и Pause.
6. **Выпуск.** Чистый commit `main`, push, только `ops/scripts/deploy-production.sh`;
   миграция сама не переключает модель. Проверить восстановление настроек и
   совместимый откат на старые профили, прежде чем считать выпуск готовым.

Обязательные сценарии автоматической приёмки:

- Разные модели двух профилей и одинаковая модель с разными уровнями сохраняются;
  неподдерживаемый уровень и устаревшая версия формы отклоняются без частичного UPDATE.
- Сквозной тест UI/API → DB → claim → подставной Codex-бинарник проверяет
  фактические `-m`/`model_reasoning_effort`, а не только JSON ответа API.
- Восемь одновременных claims при N=3 создают ровно три запуска; отключённый
  исполнитель не обходит лимит. 8 → 2 завершает старые задачи, затем соблюдает 2;
  2 → 8 сразу разрешает полезную работу. Каждому этапу доступны все N мест.
- Смена модели во время выполнения сохраняет старый снимок и выдаёт новый
  следующему запуску; старый circuit и старые QA-счётчики не загрязняют новые.
- Ошибки каталога, доступа, резерва, несовместимого CLI и недоступного bridge
  дают определённое состояние без скрытой замены модели или вечного retry.
- Pause останавливает AI в пределах 10 секунд; обычное сохранение не отменяет
  leases. Demo и пользователь без super_admin не могут менять настройки.

После выпуска выполнить ограниченные реальные проверки выбранных сочетаний
model/effort через тот же executor, включая web-задачу, структурированный
результат и High-задачу; они расходуют usage. Сопоставить argv, журнал запуска,
результат и доступные сведения runtime о модели. Затем проверить расход и Fidelity
на сопоставимом наборе сохранённых источников; модель менять вручную по результату.
До production-выпуска закрепить известные узкие grants `source_collections`
из записи corrective log от 2026-09-21, чтобы их не потерять при reconciliation.
