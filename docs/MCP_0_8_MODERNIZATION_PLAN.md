# 0.8 modernization history

Historical summary, not an active plan. The old no-push/judging restriction has
ended; follow [AGENTS.md](../AGENTS.md). Detailed milestones and dated acceptance
results remain in Git (`git log -- docs/MCP_0_8_MODERNIZATION_PLAN.md`).

Delivered themes:

- Bounded sanitized MCP request journal, retention, analytics and shared
  admin/demo views with private questions/IPs hidden in demo.
- Deduplicated learning demands, compound capability coverage, server-owned
  topics, diagnosis before discovery, replay-based closure and evidence reuse.
- Source/context applicability, evidence-bound repair, partial-artifact recovery,
  resumable reindex and short verification handles.
- Scoped circuit recovery, source/run reconciliation, coordinator reload during
  canonical deployment and production-role integration coverage.

July rollout notes include `bc7c950b585bd994efa704e4ca246320fbde05dd`, 250/250 evals
and successful unknown → prepared-source progression; that snapshot did **not**
prove the same question reached publication. Old unfinished checkboxes are not a
current backlog or permission to rerun migrations/deployments.

Superseded: four executors, single Discovery/Diagnosis, half-pool demand caps,
blanket confidence thresholds and source-wide publication. Use
[Pipeline 2.0](KNOWLEDGE_PIPELINE_2.md), [capacity](PIPELINE_CAPACITY_AUDIT.md),
[model policy](RESEARCHER_AUTOMATION.md), [Security](SECURITY.md) and
[corrective evidence](PIPELINE_CORRECTIVE_ACTION_LOG.md).

Metric definitions: a request is one public tool invocation; an error is a
structured failure; unknown means no supported answer; complete/partial coverage
must be evaluated separately from transport success. A learned demand requires
replaying the original capabilities against active revisions, not merely a
successful search, download or model run. One directly supporting official
source is sufficient evidence; a second source is not inherently required.
